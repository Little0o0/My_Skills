# Goal：自主探索有实质意义的理论算法突破

## 0. 协议身份与执行约定

- **协议 ID**：`idea-research-goal`；**版本**：`2026-09-29.3`。
- **中文规范**：`idea_goal_zh.md`；**英文执行版本**：`idea_goal.md`。两份文件表达同一协议，章节编号和硬性约束必须对应；英文版是提供给 LLM 的默认入口，不是另一个研究目标。

- 当前工作流入口使用新文件名。旧日志、冻结评审输入和备份中的 `goal.md` 是历史引用，不要求重写历史证据。


## 1. 目标与成功标准

在理论数学、计算机科学与算法领域自由探索，产出至少一项**新颖、正确、可独立复核的实质性渐近进展**。暂不以 AI Infra 落地、运行时间常数或论文包装为目标。

**主目标**：在明确且一致的问题定义、输入族、计算模型和保证类型下，显著改善已知复杂度上界，或得到同等分量的新下界。优先考虑：
- 多项式指数有实质下降，例如 `O(n²)` 到 `O(n log n)`；默认选题可将指数差 `≥0.05` 作为投入优先级参考，而非通用数学价值定律。
- 从指数时间到次指数或多项式时间，或消除决定可解性的关键参数依赖。
- 对非人为挑选的模型或问题族，证明明显更强的下界、解决一个已核实的定性开放问题。

**不单独构成达成目标**：常数因子改善、固定尺寸构造、仅有限实例的结果、微小指数或对数因子改善、复现已知定理、工具库、负面搜索日志、选题地图。固定尺寸构造若能严谨提升为符合主目标的算法族，则按提升后的定理评价，而非一概排除。

条件性定理、方法局限性定理及受限实例上的结果可以有研究价值，但不得自动替代原目标。受限问题可以被自主选为正式目标，前提是**搜索前**登记其定义与成功阈值，并通过独立价值评判；不能事后缩小范围来宣布成功。仅有条件性进展时继续追求主目标，除非用户明确修改目标。

**完成必须同时具备**：冻结后的精确定理、符合该目标事前登记的实质进展阈值、完整且经复核的证明、相对于已核实文献的非平凡增量、复核材料、无未解决的核心证明缺口，以及第 7 节的外部价值与验证结论。改善已知上界不等于证明旧上界最优；不得混淆。

## 2. 自主权限、持续执行与停止

本文件及其等义英文版是项目研究流程的当前规范。旧版 `PREREG.md`、历史评审、实验日志和 skills 中与本文件冲突的项目流程条款不再生效；用户的新指示及运行环境的权限限制优先。

- **K 无上限**：研究持续到实际达成目标，或用户明确停止。不承诺开放问题必然可解。
- 主执行者可自行选题、登记目标、改变研究策略、替换问题、分派独立 agent、在已授权资源内开展检索和实验；**不要求用户逐项确认选题或批准“冻结”**。
- 预注册的作用是保留比较口径，不是等待审批。目标更换由执行者说明理由、创建新版本并安排独立价值复评；无需证明旧题已耗尽，也不要求新题必须更难。
- 每 5 个研究轮次或出现重大证据变化时汇报一次；汇报是通知，**没有用户回复仍继续**。每轮必须围绕明确问题执行实际工作，而不只是改写计划。
- 轮次按事前登记的“具体问题—计划动作—本批工作额度或结束条件”计数；批次结束即记录有进展、无进展或工具故障，失败批次也计入，不能只给成功批次编号。连续 3 轮未形成新引理、反例、可检查构造、关键文献事实或有效排除结果时，主动重新定题、改变表示或换机制。候选停滞不等于项目停止。
- 长任务分成可恢复的小批次，保存进度、资源用量和下一步。无限轮次不等于无限费用；付费扩容、外部发布或其他超出授权范围的操作单独确认，不影响其余可做工作。
- 仅当必要的权限、服务或信息实际缺失，且没有可安全推进的替代任务时，才报告真实阻塞，并按运行环境的阻塞规则处理。**不得把自己写的审批条款、未知答案或单个候选失败当成阻塞。**
- 完成本文档整理、通过流程评审、用尽单次执行窗口，都不等于完成研究目标。当前用户若只要求编辑或评审文档，则仅执行该请求，不自行启动新实验。

### 2.1 上下文管理（强制：接近上限时自动 compact，不得因此判定完成）

- **上下文压力／注意力退化不是研究完成或真实阻塞的理由。** 应在运行器报告临近窗口上限时、下一批输入和预留输出将超出窗口时，或上下文过长造成持续错误时，提前保存检查点并请求当前接口真正支持的自动 compaction／`/compact`。
- 优先使用运行器原生自动压缩能力。仅在接口确实支持代理触发时调用对应工具或命令；把字符串 `/compact` 写进回复、shell 或子 agent 提示词**不等于压缩当前主会话**。不得声称不存在的调用能力、已生效设置或不存在的剩余 token 读数。
- 阈值必须依据实际模型／接口上下文限制、输入占用、输出预留和压缩余量设置；可将有效窗口的约 80% 作为保守启动参考，但它不是通用硬编码 token 限额。没有可靠占用信息时，缩小批次、提前检查点化，不虚构百分比。
- compact 前必须保证以下信息以文件形式存在且自洽：
  - `idea_goal_zh.md`、`idea_goal.md`：同步的目标、成功标准与执行规则；
  - `PREREG.md`：当前问题卡、基线和成功阈值；
  - `OPEN-ITEMS.md`：未决事项、证据状态和优先顺序；
  - `STATE.md`：当前候选／阶段、最新实质结果、下一步、任务句柄和资源使用；
  - `explore/`、`artifacts/`、`review/`：证明、脚本、完整原始证据和评审包。
- compact 后按 §9 的唯一恢复顺序继续，不等待额外人工“冻结”。若当前接口不能主动压缩，记录能力限制、保存检查点并使用原生自动压缩／恢复机制；在安全窗口内继续小批次任务，不谎称已执行 `/compact`，不把能力限制直接当作整个研究阻塞。
- 长任务分为可恢复小批次；每批结束更新 `STATE.md`、`OPEN-ITEMS.md`。恢复后的首个实质动作从当前最高优先级未决项产生，但须先核验它没有过期、已完成或已被反例否定；过期项先纠正再选择下一个有效任务。

### 2.2 调度、等待与防死锁

- 分派前先确定主执行者立刻可做的关键路径任务；只把具体、边界清楚、可并行且有独立交付物的工作交给 agent。不得把唯一下一步委托出去后反复空等。
- 每个任务登记负责人、读写范围、输入版本／哈希、预期输出、批次额度或结束条件，以及真实任务句柄。**同一时间一个文件只能有一个写入者**；独立评审写入独立文件，不直接覆写被审证明。
- 观察超时不等于任务失败；应检查同一句柄的权威状态，避免重复启动相同任务。需要调整或终止任务时说明原因，确认原任务终止／交接后才转移写入权；迟到产出保留为单独文件，不覆盖后来的版本。
- 每轮记录 `PROGRESS / VERIFIED_WAIT / NO_PROGRESS`：进展必须改变可检查的证据或产物；有效等待必须有当轮可验证的任务状态；没有此类证据的状态复述、未执行计划或仅增加等待次数，属于无进展。
- 有其他安全工作可做时继续，不因单一评审服务或候选卡住整个项目。核心验收门不得跳过；连续无进展按 §2 换机制，真实阻塞的判定遵循运行器规则。

## 3. 探索与问题边界

### 3.1 选题方式

先广泛侦察，再集中证明。保留若干候选问题，深入研究其中 1–2 个，不固定必须有 5 个问题或 8 个机制，也不强求每轮产生固定数量的想法。

优先比较：数学重要性、真实的已知界差距、可利用的结构、潜在新机制、证明路径、研究成本。研究密度与验证成本是参考因素，不是简单的排除规则；不把“没搜到下界”写成“没有屏障”。不能因没有廉价完备验证器而排除整个理论领域。

### 3.2 每个深入研究的目标都建立问题卡

在 `PREREG.md` 或 `explore/` 中记录：
1. 精确输入、输出及参数；区分计数、判定、报告、近似、压缩输出等不同任务。
2. 输入规模定义、允许的输入族、数域、编码和字长；注明 RAM、位复杂度、电路等模型。
3. 保证类型：确定性或随机化、最坏情况或摊还/期望、误差、失败概率及对手模型。
4. 同一口径下的最佳已核实上界、下界、条件假设、方法特定的限制；注明检索日期与不确定项。
5. 预期贡献、成功阈值、非平凡性理由、对比基线、拟突破的具体步骤。
6. 初步证明路线、最危险的假设、验证方式、下一项能区分路线成败的工作。

基础定义可先写草案；核心基线未核实前不宣称新颖或达到目标。目标口径改变时创建新问题卡，旧结论仍只属于旧版本。

## 4. 现有工作与改进空间

1. 检索原始论文、作者版本、勘误与后续工作；追踪同义术语、相近问题和重要引用链。搜索失败就明确标记未核实，不用模型记忆补造结论。
2. 关键结论须读定理及假设，而非只读摘要；记录题名、作者、版本/年份、定理位置、链接或标识符。区分发表结果、预印本与未验证声称。
3. 按统一模型建立 `GAP_MAP.md`：问题、参数区间、UB/LB、条件、来源、成本瓶颈、改进目标。多参数问题不可只挑有利切片比较。
4. 拆解最佳算法或证明：列出每一步、预处理、数据取得、存储、查询、编码解码、数值精度与重试代价；解释当前界由哪些项决定。
5. 写出“若要改善最终界，哪一项必须改变、另几项是否仍主导”。区分某个现有算法的记账瓶颈与整个方法族的下界。
6. 查新在价值评判前做一轮，在最终声明前再做一轮；发现已有结果及时更换基线或归为复现。

## 5. 构思：提出可推进的研究假设

机制可以来自分治、代数表示、数据结构与摊还、离线批处理、随机化、结构化实例、参数化、信息论、归约或新证明度量。机制清单只是提示，不构成“已穷尽”的搜索空间。

每个候选写入 `candidates/`，至少包含：
- 问题卡版本、**若成立将得到什么定量结论**、相对文献的增量。
- 一个具体机制，以及它所依赖的关键引理、构造、势函数、表示或不变量。
- 未解决的证明义务、适用范围、成本草账、可失败的预测。
- 下一项工作及其信息价值：它将支持、推翻或收窄哪条声称。

**不要求候选先被证明才有资格评价值**。尚不能形成定量猜想和关键义务的想法保留在方向池，不当成果，也不硬凑“验证候选”。

结构搜索、符号补全、SAT/SMT、传统求解器与 LLM 可混合使用；混合使用不改变各自输出的证据等级，LLM 输出仍须独立验证。先用已知正例、错误例和格式例检验工具；候选生成方式不能替代数学证明。相同输出不证明“仅记忆召回”，不同输出不证明数学新颖；失败的有限搜索也不证明方法不可能。

## 6. 阶段顺序：先价值，再验证

| 阶段 | 要做的事 | 输出与转移 |
|---|---|---|
| 侦察与登记 | 检索、规范问题、核对基线 | 问题卡与缺口地图；不等待人工冻结 |
| 假设构思 | 提出定量目标与关键证明义务 | 候选包，未证部分明确标出 |
| **价值评判** | 外部评审假定命题为真时的重要性、新颖性与边界 | 评分与理由，以及 `ADVANCE / REWORK / DEFER / REJECT` 分类决策 |
| 渐近审计 | 检查总成本、前提及模型匹配 | 暴露漏项与真正的证明负担 |
| **深入验证** | 构造证明、反例攻击、独立复核与必要的机器检查 | 明确证明状态与剩余问题 |
| 改进或换路 | 针对具体失败原因改动，而非修改成功口径 | 新版本候选；重大改动重新评价值 |
| 验收或归档 | 复查文献与全部完成条件 | 达成则报告，否则继续下一项工作 |

### 6.1 价值评判

评审者先回答：**如果结论成立，它是否值得证明？** 再讨论证明路线是否有可信入口。完整证明属于后续阶段，不得以“还没证完”为唯一拒绝理由。

按 0–4 分及文字理由分别评价：
- 进展幅度；问题重要性与范围；新颖性增量；模型与比较公平性；可推进性与复用价值。
- 分数仅用于排序，不能当作成功概率或正确性证据；阶段转移以附理由的分类决策为准。`ADVANCE` 为值得投入验证，`REWORK` 为需补清陈述，`DEFER` 为暂缓但保留，`REJECT` 为不作为主目标候选推进；这些决定不等于命题真假的判定。缺失信息标 `UNKNOWN`，不伪装为低分或零分。

重复已知结果、仅常数改善、事后换模型、违反已证下界者不得作为主目标候选前进。与**条件**下界冲突时，应明确说明将挑战哪个猜想，而非直接宣称数学矛盾；方法特定屏障也不得扩张为对所有算法的禁令。

选择通过价值门的高价值候选投入验证，不强制“top-2 无条件通过”。仅因不确定或优先级低被搁置的候选，可定期抽样复评，记录是否恢复投入；不能据此直接估计全局假阴性率。复评后仍须先通过价值门再深入验证。

### 6.2 改进规则

区分“不值得做”“陈述错误”“证明有缺口”“搜索未找到”“工具出错”和“证据不足”。只有可核验的反例或证明才能标记数学上的反驳；已证明的局限只适用于其明确限定的范围。

一次迭代须处理评审提出的核心问题，并指向新的检查结果。同一障碍连续两轮无进展时，先搁置该候选或更换机制；有新证据时可恢复。不得因评审者未能独立重证就直接判定原定理为假。

## 7. 评审角色与交叉模型要求

| 角色 | 职责 |
|---|---|
| 主执行者 | 保持 Codex 前端当前选择的主模型；选题、组织证明与实验、维护记录；可以自检，但不得独自终审自己的结果 |
| Claude Code | 独立价值评判；候选推进后以新会话复核数学与成本证明 |
| 独立本机 agent | 显式选择与主模型及相关产出生成模型不同的底层模型，并使用 `fork_context=false`；承担价值复核、反例攻击或证明复核；不替代 Claude 侧异构评审 |
| 争议复核者（必要时） | 对影响通过与否的具体分歧进行独立核查，不靠票数裁决数学真伪 |

- 用户明确要求 `tclaude` 时，必须实际调用本机 `tclaude`；其他情况下优先使用已连接的 Claude MCP，不可用时使用真实的 Claude Code CLI（包括 `tclaude`）。必须记录实际接口、工具版本、可取得的底层模型标识、输入包、输出、退出状态与文件哈希；**CLI 不得写成 MCP，工具品牌不得充当模型身份证明，未知模型不得猜测**。
- 价值包包含问题定义、候选结论、来源与增量，不含作者期望分数或其他人的判词。证明审核必须得到完整证明和假设；只有单独安排的“盲重推”任务才不提供原推导。
- 独立会话意味着隔离上下文，不意味着训练数据独立或统计独立。不得用“多个模型同意”代替证明，也不得从几个样本估算所谓理论突破成功率。
- 评审输入先保存再调用，输出原样保留。不满意的判词不得通过重试隐藏；修订后的复审使用新版本并保留前版。工具中断可重试，但须区分传输失败与实质拒绝。
- 两位评审者对核心义务或是否通过的结论存在分歧时，先列明争议、查原文或补证；仍有实质分歧，再引入争议复核者。复核不以票数推翻尚未解决的证据问题；仍未解决则不验收该候选，继续其他候选。措辞或无关评分分歧不触发无限仲裁。
- 某个外部服务暂不可用时记录缺失，继续可做的检索、证明和修订；**没有完成所需外部评审的候选不得验收**，但不因此停掉整个项目。

### 7.1 模型选择：主模型不变，审核显式跨模型

1. **主模型**保持 Codex 前端当前选择；不得为了满足评审多样性擅自切换主模型、改用户全局默认或重启会话。前端选择变化后，应对新的评审批次重新检查模型独立性。
2. **本机 agent 不得只继承默认模型**：每次调用必须显式指定实际支持的模型 ID，且所有被分派的本机 agent 都必须与主模型不同。独立评审者还必须与本次被审关键证明／构造的生成模型不同；生成或实质修订了该产出的模型，只能对此产出提供自检，不能计为独立终审。
3. 对同一候选、同一评审阶段计入门禁的多名本机评审者，底层模型必须彼此不同；同一模型可以在新会话中承担其他候选或后续阶段任务，但不能因此被计作同阶段的第二个独立模型。价值评判与证明验证分别用新会话。
4. `fork_context=false`、不同 agent 名称、不同会话、不同推理档位、同一底层模型的不同别名或上下文版本，都**不**构成模型异构性。按可核实的底层模型身份去重。
5. 评审应使用调用时最新、可访问且适合该任务的高能力模型。`gpt-6-astra`、`gpt-5.6-sol` 是用户指定的候选示例，**不是永久“最新”标签，也不是永不变化的性能排名**。每次研究运行开始、关键终审前或接口／模型发生变化时，核对官方说明、当前接口能力和可访问模型目录，保存核验日期与来源；本地缓存只能作为有时间戳的能力证据，不能凭缓存断言全球最新。
6. **强度与独立性同时满足**：在满足不同模型约束的集合中，选择与审核重要性相称的最强可用模型。若主模型或证明生成模型就是最强模型，它仍可做额外自检，但独立审核必须另选模型；用最强可用 Claude 侧模型加强关键终审，不为追求相同模型的最高分而放弃独立性。
7. 一个最小终审组合是：**Claude 侧异构评审 + 至少一个合格的不同模型本机独立评审**。这一最低组合用于研究成果验收；协议编辑按用户本次指定的审核范围执行，不为整理协议自行启动研究验收流程。两者都必须满足对被审产出的独立性要求，且其底层模型不得相同。`tclaude` 是调用入口，不保证其后端一定是 Claude；必须核实实际后端，不能用工具名称证明“跨模型／跨提供方”。
8. 若缺少合格的不同模型、模型身份无法核实或出现不可接受的降级，评审可以保留为参考意见，但不得计为所缺的正式门禁；记录 `REVIEW_INCOMPLETE`，继续其他可做工作、补齐后再验收。不得用静默回退或伪造模型 ID 解锁门禁。

### 7.2 审核重要性、推理深度与上下文

| 级别 | 工作 | 配置规则 |
|---|---|---|
| R1：辅助 | 检索整理、格式检查、简单独立复现 | 使用当前可用的合适高能力异构模型；仍须显式指定模型；辅助意见不能替代终审 |
| R2：重要 | 价值评判、查新、模型／参数匹配、复杂度审计、反例攻击 | 在合格异构模型中选高能力型号，使用该型号／接口确认支持的最深单评审推理配置，提供完整相关上下文 |
| R3：关键 | 承重引理、完整证明、反例证书、归约与检查器可靠性、争议裁决、最终验收 | 选择合格集合中的最强可用模型，使用最深支持的单评审思考模式和最大有效上下文配置；核心义务不得交给较弱快速模型作为唯一复核 |

- **参数以具体模型 × 调用接口 × 账户能力为准**。某 CLI 支持 `max`、`xhigh` 或 `ultra`，不代表本机 agent 工具支持相同值。没有确认支持前不得发送该值或宣称已生效；以调用回执／能力声明核验请求值与实际值。
- 若最深档位含自动分派，其子任务也必须满足独立性、写入权与证据要求；不能把一个自动分派调用伪装成独立评审组。不可隔离或审计这种行为时，选最深的可核实**单评审**配置并记录原因。
- **最大上下文是支持上限，不是把窗口填满的目标**。先选择当前账户和接口实际允许的最大有效窗口，不能通过虚填 token 数量扩大模型能力；为输出和工具消息预留余量。模型强弱不能仅凭窗口大小判断。
- 关键证明审核必须拿到冻结的精确陈述、全部假设、完整证明、依赖原文或足够的证明、反例／测试与义务清单。禁止只给摘要却要求“证明通过”。输入超过窗口时，分解为可追踪的局部义务审核，再由关键审核者检查依赖图、接口与全局合成；未加载或被截断的核心内容必须标 `UNREVIEWED`。
- 模型调用只需返回可检查的推导、反例、结论及剩余义务，不要求也不假装获得模型私有的隐藏思维链。

### 7.3 调用前检查与 tclaude 执行规范

每次正式评审依次执行：

1. 冻结候选／协议版本，明确本次是 `VALUE`、`VERIFICATION`、`DISPUTE` 还是 `PROTOCOL` 评审；研究候选必须先完成价值门再进入深入验证。
2. 记录主模型与产出生成模型的已知身份；选定合格的不同模型，核实模型 ID、思考档位、上下文与工具能力。身份缺失时标 `UNKNOWN`，不得把未核实的独立性写成已满足。
3. 保存输入快照、哈希和期望审查义务。完整正文可直接通过 stdin 发送；若只给路径，必须启用并确认读取工具真的成功读到了正文。
4. 调用全新隔离会话。协议 review 默认只读；优先使用最小工具集、关闭不相关自定义指令／MCP／hooks，避免被审文档自身的研究指令被当成即时行动授权。不得让评审者直接覆盖输入文件。
5. 用户要求本机 `tclaude` 时，先读 `tclaude --version` 和实际上游帮助（如该版本支持 `tclaude -- -h`），再使用该版本支持的参数。可使用 `--model`、`--effort`、`--tools`、`--strict-mcp-config`、`--safe-mode`、`--no-session-persistence` 等，但**仅当实际接口支持**。不硬编码永久有效的命令或 Claude 模型别名。
6. 保存 stdout、stderr、退出码、实际模型回执／已核实别名映射、输出哈希及任务句柄。只有“开始读取”、空输出、工具失败或退出码 0，均不构成评审完成。
7. 对反馈逐条采纳、补证或说明有证据的拒绝理由；冻结新版本并保留旧版。实质性修改后复审受影响条款，不通过选择性重试隐藏不利意见。

### 7.4 最小机器可读评审记录

正式评审至少保存以下 JSON 结构。`UNKNOWN` 是未核实，不是通过；`null` 是尚未取得字段值，不能写成 0；例如任务句柄尚未取得时也使用 `null`。路径和哈希必须对应实际文件。可以扩展字段，但不得删除身份、输入版本、覆盖范围和未决义务。

    "<verified-id-or-UNKNOWN>"

## 8. 验证与证据等级

### 8.1 必须覆盖的义务

1. **数学正确性**：定义、量词、边界情形、引理依赖、终止性、精确性或误差保证；所有核心义务逐条销账。
2. **全流程复杂度**：不能只解一个未经证明的递推式。核算输入读取、中间数据生成、预处理与查表、状态转移、输出、位长增长和随机重试。使用适合问题的递推、摊还、组合计数或概率分析，不强制套 Master 定理。
3. **表示与归约**：源任务与目标任务语义一致，证明编码/解码、代数运算、等号/平局、参数与成本均被保持；不能把一个恒等式的检查当成整条归约的检查。
4. **独立攻击**：检查难例、退化实例、极端参数、对抗序列，以及所有容易被隐藏的假设。
5. **证据可复现**：保留源码、输入、依赖版本、命令、随机种子、原始结果与失败记录；证明材料必须允许复核者复建关键推理。

### 8.2 三种证据不得混淆

- **实验支持**：有限测试、运行时间拟合、随机搜索、固定字长模拟。可发现问题；不能证明对所有规模成立的复杂度界。计时拟合不等于证明或反驳 Big-O，不能把常数项或离散分块伪影当指数变化。
- **局部证书**：在精确数域上的有限恒等式、限定逻辑内的求解器证书等。明确它证明了哪个命题、使用哪些前提、由什么检查器验证。只覆盖被检查的部分。
- **完整定理证明**：覆盖整个声明域和所有核心义务。可采用严谨的书面证明与独立逐步复核，也可采用 Lean、Coq、Isabelle 等形式化；形式化另需审计定理陈述与信任依赖，排除占位证明或未声明公理。

优先形式化最易出错、最承重的新引理；能承担时推进全证明形式化。不要求所有方向先有廉价完备验证器，也**不按最初采用的验证工具限制成果价值**。最终是否成立只取决于完整证明与审计，而不是“左栏/右栏”标签。

检查器也必须被检验：严格校验 schema、维度与数域；测试正确例、故意损坏例和边界输入。自检通过不等于检查器完备，更不等于研究定理成立。启发式求解器无解返回或超时应记为 `UNKNOWN/NOT_FOUND`，除非有适用范围清楚的不可满足证书。

### 8.3 验收规则

验收前同时确认：
- 问题卡、基线、定理、代码/构造和证明在同一模型与参数范围内。
- 主结果达到事前登记的阈值，且没有把文献已有内容或等价变形计为新贡献。
- Claude 侧异构评审与合格的本机独立 agent 已按 §7.1–§7.4 完成价值复核和相应验证复核；核心异议已用证据解决；实际模型独立性、输入版本及核心内容覆盖可核验，不能以同模型换名补足评审人数。
- 提交完整证明及“声称—证明义务—证据”矩阵；无 `UNKNOWN` 的核心义务、未证关键引理或隐藏 oracle。
- 附复核材料与明确局限。只由模型给出的肯定意见、局部恒等式证书或有限实验均不能单独过关。

满足后才可宣布研究目标完成。发表与同行评审状态另行报告，不冒称已被学界认可。

**`idea_goal_zh.md` 与 `idea_goal.md` 只保存目标、流程和验收规则，不追加修订日志、实验数字或评审得分；每次修改必须同步两份文件。**

| 位置 | 用途 |
|---|---|
| `PREREG.md` | 活跃目标、精确问题卡版本、成功阈值及替换理由；非人工审批表 |

| `review/` | 冻结审核输入、中英一致性检查、Claude/agent 原始意见、调用与模型能力记录、分歧处理和验收矩阵 |
| `artifacts/` | 构造、程序、检查器、可复现实验和环境信息 |

| `STATE.md` | 当前目标/候选/阶段、最近证据、实际任务句柄、下一步和资源使用 |

按需读取本地 research skills：文献用 `research-lit`、`novelty-check`、`citation-audit`；构思用 `idea-creator`、`research-refine`；审核用 `research-review`、`proof-checker`、`kill-argument`；实验用 `experiment-plan`、`experiment-audit`；整理用 `research-paper-writing`。只使用确实可访问的能力；缺少某个 skill 不阻塞工作。其默认模型、分数、轮次和论文导向不能覆盖本协议。

**每次恢复的唯一顺序**：`idea_goal.md`（需要澄清时对照 `idea_goal_zh.md`）→ `STATE.md` → 当前 `PREREG.md` → `OPEN-ITEMS.md` → 当前工作所需的证明／评审／脚本。先确认用户任务是文档工作还是已启动的研究；核验任务句柄与真实产物，恢复前不得仅凭旧日志推断运行状态。`NEXT-ACTION.md` 若存在只作快捷索引，不覆盖本顺序。

历史记录只作线索，不自动当真；发现错误应更新证据状态，不能沿用旧排名、旧数值或未经核实的实验解释。区分“存在一个反例／实例”“抽样未找到反例”“穷举指定有限范围”“全称定理”；不把有限样本外推成渐近上界，不把候选失败解释为所有路线已穷尽。评审快照和旧版本必须保留，当前入口不得反复复制陈旧“最高优先级”项。

**下一步行动原则**：选择最可能推进主目标、且能产生可检查新信息的任务执行。不要把反复整理流程、重复请求冻结、复述状态或不断复现小例子当作理论研究进展。
